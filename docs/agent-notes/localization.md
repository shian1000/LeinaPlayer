# Localization

The UI is written in Polish, the source language; every other language is a translation of
it. The user picks the language in Ustawienia › Wygląd › Język ("Język telefonu" by default,
Polish when the phone's language is one the app doesn't know).

## Files

- `lib/l10n/app_pl.arb` is the template: every key, with its `@key` metadata (placeholders,
  descriptions). The other `app_<locale>.arb` files hold only the translated values.
- `app_en.arb` is American English and `app_en_GB.arb` holds only the keys whose British form
  differs (spelling, dates). Serbian and Belarusian: `app_sr.arb` / `app_be.arb` are Cyrillic,
  `app_sr_Latn.arb` / `app_be_Latn.arb` Latin (Belarusian Łacinka).
- `lib/l10n/app_localizations*.dart` are generated by `flutter gen-l10n` (also by `pub get`,
  `build` and `test`, since `pubspec.yaml` has `generate: true`) and git-ignored.
- `lib/src/l10n.dart` lists the languages (`availableLanguages`, each named in itself; one
  without an `.arb` file isn't offered), resolves the phone's language (`resolveSystemLocale`:
  Serbian and Belarusian by the phone's script, English GB by country), and holds the global
  `l10n`.

## Using a text

```dart
import '../l10n.dart';

Text(l10n.settingsTitle)
l10n.songsCount(n)          // "5 utworów" / "5 songs"
```

`l10n` is a global, not `AppLocalizations.of(context)`, so data code without a context
(notifications, mood names, error messages, enum labels) uses it the same way. When the
language changes, `syncAppLocale` (called from `MaterialApp.builder`) swaps it and marks every
element for a rebuild. Widget tests that pump a bare `MaterialApp` get Polish, so the tests
keep finding the Polish texts.

Something built once and kept (a `static final` list of labels, a text in a field set in
`initState`) won't follow a language change: make it a getter or compute it in `build`.

## Keys

- lowerCamelCase, prefixed by the screen or area: `settings…`, `playlist…`, `songMenu…`,
  `privacy…`, `featureInfo…`. Shared, context-free words are `common…` (`commonCancel`,
  `commonSave`, `commonDelete`, `commonUndo`, `commonRetry`, `commonAdd`, `commonPlay`,
  `commonOk`, `commonClose`); use them only where the word means the same everywhere.
- Placeholders are `{name}`, declared in `@key` with a `type` (`String`, `int`, `double`).
  Numbers are pasted as they are (`$count`), no locale formatting.
- Counts are ICU plurals with the number inside, never a word picked in code by the number:
  `"{count, plural, one{{count} utwór} few{{count} utwory} many{{count} utworów} other{{count} utworu}}"`.
  Polish needs `one`, `few`, `many` and `other`; East Slavic languages, Croatian, Serbian and
  Lithuanian need their own categories (Lithuanian: `one`, `few`, `many`, `other`), and English,
  German, French, Greek, Hungarian, Romanian at least `one` and `other`.
- A sentence stays one message with placeholders, not pieces glued together, since word order
  differs between languages.

## What stays as it is

- Anything stored, synced, sent to MusicDatabase or matched against data: outbox request
  files, saved keys and ids, `shared_preferences` values, words looked for in YouTube or Spotify
  titles (`live`, `cover`, `remix`), regexes, music.db's own values (titles, artists, global
  mood names from tag.db).
- `debugPrint` messages and the error log (English, for whoever reads the report).
- Brand and service names: YouTube, Spotify, MusicDatabase, Leina Player (`appName`), GitHub,
  LRCLIB, iTunes, Deezer.
- Comments and doc comments: they name screens by their Polish UI text ("Ustawienia › Wygląd"),
  as the rest of the docs do.

## Tests

- The test machine's language is English, and `MusicDatabaseApp` follows the phone's:
  `test/flutter_test_config.dart` sets Polish in a `setUp`, but only where a test binding is
  already up — starting one there made every plain unit test's `HttpClient` answer HTTP 400.
- The phone's language is read through `WidgetsBinding.instance.platformDispatcher` (so the test
  value counts), falling back to `PlatformDispatcher.instance` in unit tests without a binding
  (`ThemeController.load`).
- With the app's delegates Material's own texts are Polish too, so `tester.pageBack()` (it looks
  for the tooltip "Back") finds nothing: use `tapBack` from `test/support/navigation.dart`.
  Tests pumping a bare `MaterialApp` still get English Material texts and may keep `pageBack`.

## Native (Kotlin) texts

`LinkChooserActivity`, `DownloadService` and `ScheduledMusic` read Android string resources:
`android/app/src/main/res/values/strings.xml` (Polish) and `values-<locale>/strings.xml`. The
app's language reaches them through `shared_preferences` (`appearance.language`), applied with
`AppLanguage.wrap()` in `AppLanguage.kt`, since the activity runs without Flutter.

## Adding a language

Translated so far: Polish and English (US, UK). `_allLanguages` (`lib/src/l10n.dart`) already
names the others the owner wants — German, French, Croatian, Serbian and Belarusian (Cyrillic
and Latin), Ukrainian, Russian, Lithuanian, Greek, Romanian, Hungarian — each offered once its
file exists.

1. Add `app_<locale>.arb` with every key of `app_pl.arb` (placeholders and plural categories
   checked) and `values-<locale>/strings.xml` (`values-b+sr+Latn` / `values-b+be+Latn` for the
   Latin scripts; `AppLanguage.kt` passes the saved tag to `Locale.forLanguageTag`).
2. If it isn't in `_allLanguages` yet, add it there, named in itself.
3. `flutter gen-l10n` lists untranslated keys in `build/untranslated_messages.json` (a missing
   key shows the Polish text).
4. About 1870 keys: translated in chunks of ~460 by parallel agents with one glossary of terms
   (Biblioteka → Library…) worked well; check placeholders and ICU branches by script after.
